# omp-side

为 [OMP](https://github.com/can1357/oh-my-pi) 提供上下文快照、工具调用和独立历史的旁路会话扩展，使用 TypeScript 编写。

## 特性

- [独立会话](#会话)：旁路问答和工具记录不会自动写入主对话。
- [上下文快照](#上下文)：继承创建时的主上下文，保留可见消息和文本压缩摘要。
- [工具与模型](#工具与模型)：沿用主会话的普通工具、审批策略、模型角色和认证。
- [操作菜单](#快捷键)：通过 `Alt+K` 打开，普通文字不承担快捷键功能。
- [本地历史](#历史)：按主会话保存，支持恢复、筛选、逐条删除和显式回填回答。
- 单文件安装，无需 `npm install` 或额外构建。

## 安装

需要可正常使用模型的 OMP 交互式终端。目前已验证 **Linux / OMP 18.3.4**；其他版本和平台尚未验证。

获取源码：

```sh
git clone https://github.com/Galaxy-ghost/omp-side.git
cd omp-side
```

临时加载：

```sh
omp --no-extensions -e ./side.ts
```

`--no-extensions` 关闭自动发现，但保留显式指定的扩展，适合首次试用或排查重复加载。日常使用不需要这个参数。

也可以将扩展安装到全局目录：

```sh
extension_dir="${PI_CODING_AGENT_DIR:-$HOME/.omp/agent}/extensions"
mkdir -p "$extension_dir"
cp -i ./side.ts "$extension_dir/side.ts"
```

重启 OMP 后使用 `/side`。如果文件已经位于目标目录，跳过复制即可。使用命名 profile 时，应安装到对应 profile 的扩展目录；不要同时保留多个副本。

## 功能

### 会话

打开会话列表，选择已有会话或新建会话：

```text
/side
```

也可以附带问题：

```text
/side 解释一下刚才的缓存策略
```

附带的问题在选择会话前只是待发草稿，不会自动发给上次打开的会话。列表以**主会话**为范围，而不是项目目录；恢复旧的 SIDE，需要先恢复它所属的主会话。

### 上下文

新建 SIDE 时冻结主上下文、工作目录和附加工作目录。后续追问使用该快照和 SIDE 自己的历史，不持续吸收主会话的新消息。需要更新上下文时，新建一个 SIDE。

快照保留可见消息、主会话指导和文本压缩摘要。正在生成的可见文字、工具进度和排队输入会转为只读参考，不作为继续执行主任务的请求。私有推理和不透明的 provider replay 不会复制；只有 replay、没有文本摘要时会明确报错。

通过 `Alt+K` → **查看上下文**，可以检查快照来源和实际工具情况。

### 工具与模型

默认使用 `@smol`。通过已有的聊天角色指定模型：

```text
/side --model @slow 检查一下这个方案的边界条件
```

也可以在操作菜单中选择模型角色。角色必须已配置且可用，`--model` 不接受裸模型 ID。

普通工具在每次提问前刷新，新调用遵循主会话当前的启用状态和审批策略。`task`、`goal` 及已知的 `vibe` 工作线程管理工具被排除；不能从 SIDE 或子代理里再创建 SIDE。

原生选择、确认、输入等交互按顺序展示。第三方扩展的界面能力并非全部兼容：无法呈现的装饰会提示，不支持的交互方法会报错。

### 快捷键

`Alt+K` 打开或关闭操作菜单。菜单内用方向键选择、Enter 执行、Esc 返回。历史、工具输出、模型、上下文、筛选和回填等操作都在菜单中。

| 按键 | 操作 |
| --- | --- |
| `Alt+K` | 在会话列表、对话或历史页开关操作菜单 |
| `Enter` | 发送问题，或打开当前选项 |
| `Esc` | 关闭菜单或返回上一级；从会话列表返回 MAIN |
| `↑` / `↓`、`Home` / `End` | 在列表中选择；输入框内保持编辑行为 |
| `PgUp` / `PgDn` | 翻页；在对话页滚动输出 |
| `Ctrl+C` | 取消当前 SIDE 回答 |
| `Ctrl+W` | 关闭当前 SIDE，保留历史 |
| `Delete` | 在列表或历史页发起删除确认；输入框内正常编辑 |

空输入框仍是输入框。`h`、`q`、`/`、`?`、`gg`、`dd` 等不会触发命令。菜单关闭后保留草稿并恢复输入焦点。

删除只接受 `y` 确认；`n`、Esc 和 Enter 都是取消。回填回答只放入 MAIN 草稿，不自动发送。

### 历史

默认保存位置：

```text
~/.omp/agent/side-history/<主会话 ID 的 SHA-256>/
```

使用 `PI_CODING_AGENT_DIR` 或 profile 时，跟随实际 agent 目录。`thread-*.json` 保存线程元数据和快照，`turn-*.json` 保存问答。

| 操作 | 结果 |
| --- | --- |
| 返回 MAIN | 隐藏页面，SIDE 可继续运行 |
| 取消回答 | 停止当前回答，保留已经产生的内容 |
| 关闭会话 | 中断运行并取消待处理交互，历史可重开 |
| 删除问答 | 移除选中记录，后续上下文按保留记录重建 |
| 丢弃会话 | 删除该 SIDE 的记录和快照 |

历史是本地明文，可能包含项目内容和工具结果；目录名哈希不代表加密。卸载扩展不会删除历史。

## 开发

运行入口是 [side.ts](side.ts)，变更记录见 [CHANGELOG.md](CHANGELOG.md)。扩展使用 OMP 内部 SDK，升级宿主后需要重新验证。

目前以真实 TUI 手动回归为主，没有独立的自动化测试套件。使用临时 `PI_CODING_AGENT_DIR` 或独立 profile 加载修改后的扩展，检查：

- 会话选择、上下文隔离和连续追问。
- 普通输入、`Alt+K` 菜单、草稿恢复及窄屏缩放。
- 工具交互、隐藏、取消和关闭后的历史恢复。
- 回填不自动发送，删除确认不影响其他记录。

不要用真实会话验证删除。诊断渲染耗时可使用 `SIDE_PERF=1 omp`，计时追加到 `/tmp/side-perf.log`。

仓库使用 `.gitignore` 白名单，避免纳入其他扩展或私人运行数据。添加项目文件时需要同步更新白名单。

## 常见问题

### SIDE 是只读的吗？

不是。SIDE 隔离对话，不隔离操作系统环境。允许写文件的工具仍可修改同一个工作区；取消、关闭或删除历史都不会撤销已发生的工具副作用。未知扩展也可能拥有自己的外部能力。

### 删除一条问答会清除它的所有影响吗？

不会。后续回答可能已经引用其内容，文件或外部服务也可能已经发生变化。删除记录不是追溯擦除或事务回滚。

### 会自动写入共享记忆吗？

SIDE 关闭了自动记忆读写等后台行为。无法安全隔离的配置会阻止启动，包括 sharpshooter，以及通过环境变量强制开启自动记忆的 Hindsight。显式工具调用和第三方扩展的副作用不在这个保证内。

### 可以在无界面模式使用吗？

不可以。`/side` 依赖交互式 TUI，不支持 `omp -p` 或无界面的 RPC 模式。

### 使用什么许可证？

目前未指定开源许可证。
