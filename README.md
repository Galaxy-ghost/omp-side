# OMP SIDE

做主任务时，经常会冒出一些值得问、又不值得把整段对话带跑的问题：这段代码为什么这么写？有没有另一种实现？刚才提到的东西能不能展开讲讲？

SIDE 就是给这些问题留的地方。在 [OMP](https://github.com/can1357/oh-my-pi) 里输入 `/side`，打开一个独立的会话页。它带着主会话的上下文，可以读文件、查代码、用工具，但不会把旁路里的问答和工具记录自动塞回主对话。

不是常驻侧栏，也不是另一套聊天客户端。项目本身只有一个运行文件：[side.ts](side.ts)。

## 怎么用

```text
/side
/side 解释一下刚才的缓存策略
/side --model @slow 帮我挑一下这个方案的问题
```

无论有没有附带问题，都会先打开会话列表。选择已有会话，或者选择“＋ 新建会话”，才会进入对应的对话；附带的问题在选择之前只是待发草稿，不会悄悄发给上次打开的会话。

默认使用 `@smol`，模型和认证沿用 OMP。`--model` 接受已有的、可用的聊天角色，不接受裸模型 ID。进入会话后也能在 F1 菜单里换角色。

列表只显示**当前主会话**的 SIDE。同一个项目目录里的两个主会话，不会共用一份旁路列表。想继续旧的 SIDE，需要先恢复它所属的主会话。

## 安装

需要能正常使用模型的 OMP 交互式终端。当前在 **Linux / OMP 18.3.4** 上验证；这个扩展使用了 OMP 的内部 SDK，升级 OMP 后不能默认认为一定兼容。

拿到仓库、进入目录后，可以先临时加载：

```sh
omp --no-extensions -e ./side.ts
```

`--no-extensions` 关闭自动发现，显式指定的 `-e` 仍会加载，适合排查重复安装或其他扩展的干扰。它不是日常使用的必要参数。

长期使用，把 `side.ts` 放进 OMP 的全局扩展目录即可。如果文件已经在那里，跳过复制，重启 OMP 就行。

```sh
extension_dir="${PI_CODING_AGENT_DIR:-$HOME/.omp/agent}/extensions"
mkdir -p "$extension_dir"
cp -i ./side.ts "$extension_dir/side.ts"
```

复制后重启 OMP，输入 `/side`。使用命名 profile 时，以那个 profile 实际使用的扩展目录为准。不要同时保留多个 SIDE 副本。

不需要 `npm install`，也没有单独的构建步骤：TypeScript 文件和 SDK 导入交给 OMP 加载器处理。`/side` 需要真实的交互式 TUI，不能拿 `omp -p` 或无界面的 RPC 模式代替。

## 按键，尽量少记

输入框就是输入框，**空着也不会变成命令模式**。首字母 `h`、`q`，以及 `?`、`gg`、`dd`、`yy`、`za` 都是普通文字。

| 按键 | 作用 |
| --- | --- |
| F1 | 打开或关闭当前页面的操作菜单 |
| Enter | 在输入框发送；在列表或菜单打开所选项 |
| Esc | 关菜单、返回上一级；从列表返回 MAIN |
| ↑ / ↓ | 在列表和菜单中选择；输入框内交给编辑器处理 |
| Home / End | 在列表中跳到首尾；输入框内保持编辑行为 |
| PgUp / PgDn | 翻页；在对话页滚动输出 |
| Ctrl+C | 取消当前 SIDE 回答 |
| Ctrl+W | 关闭当前 SIDE，保留历史 |
| Delete | 在会话列表或历史列表中发起删除确认；输入框内正常删除文字 |

历史、复制回答、展开工具输出、模型角色、上下文检查和筛选等操作都在 F1 菜单里。菜单里的“回填”只把所选回答放进 MAIN 的草稿，**不会代你发送**。

删除需要明确按 `y` 确认；`n`、Esc 和 Enter 都是取消。

## 上下文到底带了什么

新建 SIDE 时，会冻结当时的主上下文、工作目录和附加工作目录。之后的追问沿用这个快照以及 SIDE 自己的历史，**不会持续吸收 MAIN 后来新增的消息**。想带上新的主上下文，就新建一个 SIDE。

快照包括可见消息、文本压缩摘要和主会话指导。主会话正在生成的可见文字、工具进度，以及排队中的输入，会转成只读参考，明确标记为不能接着执行的主会话活动。

不会复制私有推理或不透明的 provider replay。如果主会话只有不透明 replay、没有能用的文本摘要，SIDE 会报错，而不是装作继承成功。F1 → 上下文可以查看实际快照来源和工具情况。

这里有个区别：**对话上下文是冻结的，普通工具能力会刷新。** 每次提问前，SIDE 会同步主会话当前启用的工具；新调用也会检查主会话的撤销与审批状态。

## 它隔离什么，不隔离什么

SIDE 隔离的是对话记录，不是操作系统环境。

- 工具能做什么，取决于主会话启用了什么，以及当前审批策略。它不只是一个只读问答框；允许写文件的工具，仍然可能修改同一个工作区。
- `task`、`goal` 和已知的 `vibe` 工作线程管理工具被排除。不能从 SIDE 或子代理里再创建 SIDE。未知扩展可能有自己的外部能力，这不是对任意插件代码的安全沙箱。
- 原生选择、确认、输入等工具界面可用，MAIN 和 SIDE 的交互请求按顺序展示。不是每种扩展 UI 都兼容：widget、页眉、页脚等装饰可能无法呈现，会明确提示。
- SIDE 关闭了自动记忆读写等后台行为。无法安全隔离的记忆配置会阻止启动，包括 sharpshooter，以及通过环境变量强制启用自动记忆的 Hindsight。显式工具调用和第三方扩展自己的副作用，不因此自动消失。

尤其要区分这几件事：

| 操作 | 后果 |
| --- | --- |
| 返回 MAIN | 只是隐藏，SIDE 可以继续运行 |
| 取消回答 | 停止当前回答，保留已经产生的内容 |
| 关闭 SIDE | 中断当前运行并取消待处理交互，历史还能重开 |
| 删除一条问答 | 移除该条 SIDE 记录，后续上下文按保留的记录重建 |
| 丢弃整个会话 | 删除该 SIDE 的记录和快照 |

**以上操作都不会撤销工具已经写入的文件、发出的请求或其他外部副作用。** 后面的回答也可能引用前面的内容，逐条删除不是对所有文字的追溯擦除。

## 历史存在哪里

默认在：

```text
~/.omp/agent/side-history/<主会话 ID 的 SHA-256>/
```

设置了 `PI_CODING_AGENT_DIR` 或使用 profile 时，跟随实际 agent 目录。线程元数据和快照保存在 `thread-*.json`，问答保存在 `turn-*.json`。

这些是本地明文文件，可能包含项目内容和工具结果；目录名做哈希不代表加密。备份、分享或清理时，请把它们当会话数据处理。卸载 `side.ts` 不会顺便删除历史。

本仓库的 `.gitignore` 使用白名单，只跟踪扩展和维护文件。这样即使仓库就放在全局 `extensions` 目录里，也不会顺手把其他扩展、配置、密钥或运行数据提交进去。新增项目文件时，需要一起更新白名单。

## 修改之后怎么检查

目前以真实 TUI 的手动回归为主，没有独立的自动化测试套件。修改后直接加载到 OMP，至少检查这些路径：

1. `/side 问题` 先停在列表，选择“新建”后才发送；换一个主会话看不到原来的列表。
2. 在空输入框输入 `hello?`、中文、`gg`、`dd`。它们应立即显示为文字。打开、关闭 F1 菜单后，草稿和输入焦点还在。
3. 发送问题，查看回答和工具输出；返回 MAIN 不取消，Ctrl+C 取消，Ctrl+W 关闭后还能重开历史。
4. 从 F1 打开历史并回填回答，确认 MAIN 只有草稿，没有自动发送。
5. 删除问答和丢弃会话分别验证一次：Enter 不能确认删除，`y` 才能；不应影响别的会话。
6. 缩窄终端、减少高度再恢复，检查菜单选择、输入框、滚动位置和光标。

测试应使用单独的 OMP profile 或临时 `PI_CODING_AGENT_DIR`，别拿真实会话验证删除功能。用本地模型替身可以检查界面流程，但不能据此判断真实模型的延迟、输出质量或远端工具表现。

需要排查渲染耗时时，可用 `SIDE_PERF=1 omp` 启动，计时追加到 `/tmp/side-perf.log`；正常使用无需开启。
